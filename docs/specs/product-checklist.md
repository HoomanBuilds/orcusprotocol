Implementation checklist for this repository. IDs link to the [implementation plan](../plans/implementation-plan.md). Source provenance is recorded separately in the [reuse inventory](../research/reuse-inventory.md).

Build a personal-agent trading platform where users can research, trade and manage positions themselves or through their authorized agent. Both interfaces operate on the same supported trading accounts. Privacy supports the product; it does not turn public trades into private transactions.

Sponsor targets: **0G + Uniswap + Chainlink CRE**. Hyperliquid is an additional trading integration, not a fourth sponsor target. Target the CRE workflow bounty; CCIP and Anon-RPC are not required integrations.

Hosting scope: a normal single-EC2 testnet hackathon demo, as described in the [AWS runbook](../../deploy/aws/README.md). First-run setup, the web process, an authenticated worker and local persistent session/account state are included. Production backups, high availability, KMS, managed databases and a monitoring platform are not required. Strict TEE, earned funding and automatic compute replenishment remain optional, not reasons to delay the basic demo. External credentials, testnet funding and actual hosted transaction acceptance remain separate from code completion.

This is the implementation checklist in build order. A checked item means the feature and its safeguards are implemented with the local, fixture, fork or dated live evidence stated here. It does not imply current provider availability, public deployment or complete browser-extension acceptance. Unchecked items are remaining combined acceptance, publication or explicitly optional requirements. The table below keeps external gates separate from feature completion.

## Reviewed automation safety follow-up

- [x] Require an owner-reviewed executable trade and an explicit schedule or supported typed price condition before activation. An AI proposal is only a draft until the owner accepts it; the worker executes that fixed request without silently asking a model to rewrite it.
- [x] Default new trade jobs to one submission attempt. Recurring and threshold-crossing jobs require a finite execution cap; consumed attempts persist across restarts and cannot be reset by resume or policy edits. Unknown submission outcomes consume an attempt and are never automatically replayed.
- [x] For crossing mode, observe the initial threshold state without trading, then trigger only on a false-to-true transition. Record arming, waiting, notification and submission separately from a CRE allow decision. Price alerts do not submit trades.
- [x] Pause older unversioned policies for explicit structured review. Revalidate account ownership, current delegated permission, expiry and market binding on changes; instruction-only edits cannot silently modify an approved trade.
- [x] Bind CRE evidence to the exact reviewed condition, account, request and policy version. ETH/WETH aliases are intentional; unrelated trade and trigger markets are rejected before evaluation.
- [ ] Arbitrary RSI, news, sentiment, multi-leg and free-text predicates are not supported automatic triggers. Ask for clarification or keep them as research until a typed evaluator is implemented. Local fixture coverage is not public settlement or hosted CRE deployment evidence.

## Scope boundaries

- No token launch, compulsory pooled vault or invented private-trading mode.
- No forced Hedera, Arkiv, Anon-RPC, CCIP or extra sponsor integration.
- No claim that merely connecting a wallet authorizes the agent or makes every existing position controllable.
- No promise of arbitrary venue support. Add adapters without changing the ownership and permission model.
- Keep all manual and agent capabilities above in the hackathon product; these are build-order checkpoints, not a six-month release roadmap.
